# 切片工作台 · colorfulver 方向配色版

这是从当前的 `field-slice-viewer-web-gpu-20261106-v1` 复制出的独立版本，保留多箭头优化、GPU 选项与 100 倍缩放。原文件夹保持不变。本文件夹包含 12 个网页运行文件和这份说明，没有测试数据、历史版本或开发依赖。

## 打开与导入

1. 解压整个文件夹，保持文件之间的相对位置。
2. 用浏览器打开 `index.html`。
3. 将 `.bfslice`、`XY.` 或 `XZ.` 开头的五列文本文件拖入导入框，或点“选择文件”。
4. 需要操作介绍时，点“使用教程”。教程仍为原来的 10 步，使用独立的合成示例。

网页无需安装 Python、Node.js 或第三方图形库；不需要云端计算。数据读取、绘图、GPU 调用和 PNG 导出都在本机完成，代码不上传数据。若浏览器所在环境限制直接打开本地网页，也可以使用任意静态网页服务器打开同一个文件夹；服务器只负责提供这些静态文件。

`.bfslice` 支持 P/AFD 的 float32/float64 原始场。XY/XZ 文本每行依次为 `x、y或z、px、py、pz`，仍按单切面处理。坐标按格点显示。单文件限制仍为 128 MiB。

左下角的鼠标读数分为两行：第一行显示整数格点坐标，第二行显示 P 或 Φ 的三个分量，保留四位有效数字。XY/XZ 单切面文件只显示文件提供的两个坐标。数值格式仅影响文字显示，不修改原始数据；切换文件、层或显示设置时会清空旧读数，移动鼠标后显示当前格点。左右底部状态文字使用统一样式。

## 新增：箭头方向颜色与左图热图开关

“箭头外观”栏目集中提供“左图箭头颜色”“右图箭头颜色”和“方向配色 · 色环与色球”，修改后立即刷新；初始仍为左图纯黑箭头、右图按 z 分量色标着色。

- **左图箭头颜色 → 平面方向**：XY 切面按 `(px, py)` 方向着色，XZ 切面按 `(px, pz)` 方向着色。旁边的彩虹色环显示当前切面的方向对应关系。投影为零的矢量不画平面箭头。
- **关闭热图渲染**：隐藏左图的标量底色，保留箭头、坐标、框选、滚轮缩放和右键平移。按钮变为“开启热图渲染”，再次点击恢复。该开关不影响右图边界长方体的六面热图。
- **右图箭头颜色 → 空间方向**：用原始三维矢量 `(px, py, pz)` 的单位方向着色，适用于体内箭头和边界长方体上的箭头。色球随三维视角同步旋转；转动图像可查看另一半球的方向颜色。颜色固定在数据 x/y/z 坐标系内，不随相机改变。体素模式不使用箭头方向颜色，返回箭头模式后恢复原选择。
- AFD 数据使用同样的规则，对应分量为 `Φx、Φy、Φz`。
- 原来的配色、双色和 colorbar 上下限继续控制**标量热图与按 z 分量着色的箭头**；不会改变方向色环/色球；方向配色由“箭头外观”中的预设单独控制。
- Ctrl+Z / ⌘Z 可撤回颜色模式与热图开关。

### 方向配色预设

| 预设 | 特点 |
| --- | --- |
| 经典彩虹（原版） | 保留原版的平面色环与三维赤道彩虹顺序。 |
| 柔和彩虹 | 降低饱和度，使用柔和的粉、橙、绿、青、紫循环。 |
| 青紫橙环 | 由青色经过蓝紫、洋红、橙黄与绿色，闭合回青色。 |
| 蓝红金环 | 由蓝紫经过红、橙金、青绿，闭合回蓝色。 |

后面三种为本网页自定义的循环配色，不冒用其它标准色图名称。左右图共用当前方向预设；箭头、色环、色球与 PNG 图例同步更新，PNG 中还会写出预设名称。切换预设可用 Ctrl+Z / ⌘Z 撤回，不会重新分配箭头几何缓存。

预设只改变方向颜色，不改变矢量、采样密度、大小、热图或显示范围。经典彩虹保留原平面色环算法；新增预设在 8 个 RGB 色点之间周期线性过渡，末色与首色连续连接。四种预设的三维两极统一使用彩色：+z 为橙金色 `#f59526`，−z 为蓝紫色 `#5c3dcb`，不再使用黑白或灰色两极。

### 如何读方向图例

平面内，以 +x 为零度，逆时针经过 +y（XZ 为 +z）、−x、−y（XZ 为 −z）。在“经典彩虹（原版）”中，对应主要颜色为红、黄绿、青、紫；其它预设请以当前色环为准。色环只表示方向；箭头长度仍表示投影矢量模长。

三维图采用连续的“方位配色 + 彩色两极”映射：赤道采用当前方向预设，向 +z 逐渐混合为橙金色，向 −z 逐渐混合为蓝紫色。色球当前可见的三个有符号坐标标签与三维图视角一致；箭头、色球和导出 PNG 使用相同定义。

具体约定：令 `n = P / |P|`，`H = atan2(ny,nx)/(2π)`（周期归一至 0–1），赤道 RGB 颜色为 `c(H)`，对应半球的极点颜色为 `p`，则三维 RGB 颜色为 `(1−|nz|)×c(H) + |nz|×p`。经典彩虹的平面方向仍使用 HSL 的 `S=1、L=0.5`。这是本网页的显示约定，不是新增物理量；读取方向时请结合色球与坐标标签。零向量没有方向，不绘制三维箭头。

方向模式下颜色与矢量模长无关；三维箭头保持圆锥形头部，但不再叠加会改变方向颜色明暗的光照着色。原 z 分量模式保留已有光照效果。GPU 与兼容绘制使用同一个颜色定义。

### 比例尺与保存 PNG

左图“保存平面 PNG”旁的“设置比例尺”会打开弹窗：

1. 输入一个格点对应的 nm 数，例如 `0.4`。这里指显示坐标相差 1 格点的实际长度；不会自动使用文件头中的长度，也不会改变源数据或坐标输入框。
2. 输入要画出的比例尺长度，例如 `5` nm。
3. 点击“确定”。图片右下角显示白色填充、黑色边框的矩形比例尺，上方标注 `5 nm`；上述例子的横向长度为 `5 / 0.4 = 12.5` 格点。
4. 按钮变为“取消比例尺”，再次点击即可移除；如需更改数值，可先取消再重新设置。添加、取消比例尺也支持 Ctrl+Z / ⌘Z 撤回。

比例尺随当前选区的绘图缩放实时更新，XY/XZ 切换保留校准。两个输入必须是有限正数；长度太短、过长或图片太窄/矮而放不下时会提示。若随后缩放选区导致放不下，比例尺暂停显示，带比例尺导出会要求调整，避免绘制或保存错误长度；无文字导出仍可使用。导入新文件后校准清空，需要重新设置。

两张图各有独立的导出下拉框，选择方式后再点击相邻的保存按钮：

| 输出方式 | 平面 PNG | 三维 PNG |
| --- | --- | --- |
| 完整图片（未设置比例尺） | 图片、格点坐标、切面/层说明及当前颜色图例。 | 图片、坐标方向、层说明及当前颜色图例。 |
| 图片与比例尺（设置后自动替代平面的“完整图片”） | **只有当前选区图像和比例尺**，去掉 x/y 或 x/z 坐标、刻度、层说明及颜色图例；输出裁切到实际绘图范围。 | 不受左图比例尺影响。 |
| 保存无文字图片 | 只有当前选区图像，不含坐标、刻度、说明、图例，也不含比例尺；不改变网页上的比例尺状态。 | 只有三维图像，不含坐标方向标记、说明、色球或 colorbar；保持当前视角与完整设定密度。 |

导出继续支持 72–600 DPI，并写入 PNG 的 DPI 元数据。上方会根据两图各自的输出方式显示像素尺寸；无文字/带比例尺的平面导出按实际图像宽高裁切，通常小于带图例的完整图片。按当前 DPI 重新绘制原始热图与箭头，不会放大预览截图。3D 关闭时不能导出三维图。

完整图片的图例自动匹配：方向箭头附带色环或色球；若同时存在热图，再附带竖向标量 colorbar。仅有纯黑箭头且热图关闭时，没有颜色图例。方向图例放在独立的右侧留白区，不遮盖数据。文件名以 `-scalebar` 或 `-clean` 区分新增导出方式。

## 新增的渲染选择

右图上方增加两个选项，适用于“体内箭头”和“边界长方体”。体素模式继续使用原有渲染路径，这两个选项在体素模式下暂时禁用。

| 选项 | 行为 |
| --- | --- |
| 自动（优先GPU） | 默认选项。尝试使用 WebGL2；不可用或出错时回退到兼容绘制。 |
| GPU加速 | 使用相同的 GPU 路径；不可用时仍会回退，并在右图下方说明。 |
| 兼容绘制 | 使用 Canvas 绘制，不要求 WebGL2。 |
| 交互优先 | 默认选项。旋转、缩放或调整参数时，临时减少显示箭头数量；操作停下约 0.2 秒后，开始恢复设定密度。 |
| 始终完整密度 | 不额外做交互抽样。箭头很多时仍采用分批绘制，完整画面需要更长时间形成。 |

“GPU · WebGL2”表示使用了 WebGL2 渲染路径。是否实际由独立显卡、集成显卡或浏览器的软件图形实现执行，取决于浏览器和系统驱动；网页不能保证强制调用某一张显卡。显示“兼容 · Canvas”时也可以正常使用。

右图下方会显示“交互预览”“正在细化”或“显示”，以及已画出/目标箭头数。文字较长时可将鼠标停在该处查看完整说明。

## 大数据时如何操作

- 三维滚轮缩放范围为初始视角的 **0.25–100 倍**（原上限为 5 倍）。点“重置视角”回到 1 倍，Ctrl+Z/⌘Z 可撤回缩放。
- 推荐保留“自动（优先GPU）”和“交互优先”。默认 X/Y/Z 箭头间隔仍为 **4、4、2**。
- 单个视图的估算箭头上限从 8 万提高到 **200 万**。上限按设置的采样位置估算；零向量不会绘制箭头。
- 拖动预览只抽取原有格点箭头，不插值、不平均。停止操作后恢复当前 X/Y/Z 间隔与选层所要求的全部非零箭头。
- 兼容模式的交互预览最多显示约 1500 支箭头。GPU 预览预算会根据交互耗时调整。
- 大图恢复期间可以继续旋转、缩放、换文件或关闭 3D；过时的分批任务会取消。
- 保存 PNG 使用当前设置的完整密度，不会把临时交互抽样当作最终结果。完整图片导出附带当前模式对应图例，无文字导出省略图例，均支持 72–600 DPI。大量箭头、高 DPI 导出会比预览慢。
- 需要更快得到完整画面时，可以增大箭头间隔、减少显示层数，或改用边界长方体模式。

左图框选、滚轮缩放、右键平移、XY/XZ 切换、持续跟随“仅左图层”、自定义配色、箭头大小、Ctrl+Z/⌘Z 和关闭/开启 3D 均保留。

## 这次优化了什么

箭头位置与矢量存入紧凑缓存；改变相机、颜色或箭头大小时复用缓存。GPU 端使用实例化批量绘制，并直接显示到画布，交互时不逐帧把整幅 GPU 图像读回 CPU。每支箭头用 12 个顶点表示柄部和圆锥包围面，圆锥表面与深度由着色程序计算，保持圆锥外观。大批量完整绘制可以分段取消。

兼容模式用线性的深度分桶代替每帧对象排序，用投影圆锥轮廓代替逐个三角面绘制；准备和绘制均切分成短任务。兼容模式的遮挡仍是画家顺序近似，GPU 模式则使用深度缓冲。

原始导入场保持原精度，不改写源文件。三维显示缓存使用 float32；显示结果不应代替对原始 float64 数据的定量分析。

实现参考：[WebGL2 实例化绘制](https://developer.mozilla.org/en-US/docs/Web/API/WebGL2RenderingContext/drawArraysInstanced)、[WebGL 性能建议](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)。

## 原多箭头优化版的验证记录与限制

以下性能数字来自复制前的版本，不能当作本次新增方向配色后的测量值。

本次内置浏览器没有开放 WebGL2，因此浏览器性能测试实际运行的是兼容模式；没有可用的实体显卡，不能将下面结果称为独立显卡实测。

在同一测试环境、720 × 650 内部画布下，合成三维数据的代表性结果如下。交互预览绘制 1500 支原始箭头；静止后再补齐全部数量。

| 目标箭头数 | 交互单帧绘制中位数 | 交互更新间隔中位数 | 静止后完整绘制 |
| ---: | ---: | ---: | ---: |
| 80,000 | 7.7 ms | 26.9 ms | 约 1.0 s |
| 1,000,000 | 7.8 ms | 26.5 ms | 约 14.2 s |
| 2,000,000 | 7.7 ms | 25.8 ms | 约 28.8 s |

因此，两百万箭头场景的交互更新约为每秒 38 次，完整静态图仍需要等待。这是交互预览的测试结果，**不是两百万箭头完整逐帧渲染的帧率**，也不是对其它电脑的帧率保证。旧版同机 8 万箭头完整帧的代表性耗时约 3.0 秒。

GPU 着色程序另外在 Mesa 软件 OpenGL ES 环境中编译、链接并执行：64 种方向、三种头部大小与 128 边圆锥参考图比较，轮廓交并比均超过 99.9%；分批与整批图像一致，遮挡不依赖箭头提交顺序。还验证了两百万实例纹理、1 万支交互抽样。此测试验证着色程序，不等同于真实浏览器硬件 GPU 验收。

浏览器核验包括真实 P/AFD 文件、XY/XZ 文本、坐标映射、配色与大小调整的缓存复用、边界六面、选层跟随、撤回、关闭/开启 3D、换文件中断、体素切换、300 DPI 导出、鼠标旋转缩放和完整十步教程。
